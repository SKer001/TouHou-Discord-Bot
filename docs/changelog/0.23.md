## 0.23.000 — 2026-11-05：經濟系統 (神社經營、浮動市值、分解、市場、轉帳)
- **⛩️ 神社經營 `/shrine manage`、`/shrine collect`**：賽錢箱每小時 5,000 × 效率 (上限 200K，要回收)；清掃 (每 4 小時髒一階，每階 −10%)；治退妖怪 (每小時機率生成 80/70/55/35/10%，最多 5 隻，每隻 −8%，打退 +1,000 並留下晦氣 −1 階清潔度)；參拜客 (每 2 小時 90/80/70/60/50%，最多 5 位，心情每 4 小時 −10%，0 就離開)。
  - 招待 (每份 1,000 × 心情²) 需要餐點，等素材副本做好再開放，按鈕先停用。
- **💹 浮動市值 `/market price`**：官方回收價 N 50 ～ LR 50,000 為保底；每天台灣 00:00 結算，賣出 (市場 + 分解) 對比「當天新抽到張數 × 50%」，3 倍 / 三分之一時 ±10%，沒人賣 +2%。完整度倍率用曲線 (0 ➔ ×0.2、0.5 ➔ ×1、1 ➔ ×1.2)。
- **♻️ 分解 `/market decompose`**：依市值 × 完整度倍率換賽錢，可跨頁多選。
- **🏪 市場 `/market sell / browse / mine`**：不限價格，買家付 1.05 倍，7 天沒賣出自動下架；上架中的卡移到託管表，不能拿去合成 / 融合 / 分解。
- **💸 轉帳 `/trade`**：手續費 5% 從金額扣，每人每天最多轉出 500K。
- 市場與轉帳要**累積簽到 7 天**才開放 (新增 `users.daily_count`)；現有玩家在欄位補上時直接填 7。
- 抽卡選項與「繼續祈願」按鈕的價格改成從 `DRAW_COST` 算 (0.22.000 漏改，還顯示 2,000)。
- 問題：神社、市值都跟時間有關，但機器人沒有背景排程。解法：跟體力一樣在查看 / 操作時才結算 — 神社從上次結算時間一路推進 (整點事件、變髒的時間點切段算收入)，市值在第一次有人用市場時補算前幾天；太久沒來只模擬最後 14 天 / 60 天。
- 問題：市值的結算規則需要「每張卡的抽中機率」，但卡池在抽卡模組裡。解法：市場模組用 `importlib` 從抽卡模組取 `GACHA_POOL` 算機率再傳給資料層，資料層不依賴 Cog。
