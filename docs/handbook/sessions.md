## 1. 共同規則與大家都踩過的坑
這一節每個角色都要看。規則的原文在 `docs/handbook/workflow.md`，這裡只寫「為什麼」和實際出過的事。

### 1.1 版本號最後才編
- **出過的事**：三個角色同時推 `main`，0.35.006、0.35.009 兩次撞號 (都是先編號、後 pull)。
- **做法** (0.35.011 起)：先 commit 內容，CHANGELOG 標題先寫 `## 0.XX.??? —`；要推的時候 `git pull --rebase` ➔ 看 main 上 `Utils/version.py` 最新是多少 ➔ 填「最新 + 1」➔ `git commit --amend` ➔ 馬上 push。被拒就再 pull 重編。CHANGELOG 衝突兩邊都留。
- **0.35.013 推出空的版本號**：用 `python -c` 讀 `version.py`，Windows 預設 cp950 讀 UTF-8 檔失敗，拿到空字串就推了。➔ 讀檔一律 `encoding="utf-8"`，寫入前檢查格式是 `X.XX.XXX`。
- **0.39.003 的 commit 訊息版本號是空的**：用 `cut` 拆 `VERSION = "…"` 的引號拆壞。➔ 直接用 Python 讀出來再組訊息。
- **0.35.014 漏推程式**：`git stash` ➔ 換到最新 main ➔ `stash pop` 之後檔案變回「未暫存」，結果只 add 了版本號。➔ commit 前一律重新 `git add` 全部要推的檔案，再 `git status` 看一次。stash 是所有 worktree 共用的，能不用就不用。

### 1.2 同一個 Token 同一時間只能有一個機器人在跑
- 兩邊同時用正式 Token 執行 `python Main.py` = 兩個機器人同時回應、各寫各的資料庫。兩台電腦之間是這樣，雲端上線後本機 ⇄ 雲端也是。
- `Database/Users.db` 是二進位檔，git 沒辦法合併：兩邊都改過就只能挑一邊。
- 測試、`tools/botcli.py`、`botcli --live`、`tools/discord_peek.py` 都不連 Gateway (只用 REST 或完全不連)，機器人在別處跑的時候照樣能用。
- 雲端上線後，本機要用正式 Token 跑之前先 `python deploy/handoff.py take`，用完 `release` (`docs/dev/deploy.md`)。

### 1.3 Windows 上寫檔、跑 Python
- **Bash heredoc 寫 Python 會壞**：字串裡的 `\n` 被變成真的換行、反斜線被吃掉、`'''` 配中文引號被當成沒關的字串。CHANGELOG 裡記了至少 7 次 (0.29.000、0.30.017、0.35.000、0.35.084～0.35.087、0.37.000)；這份手冊第一次寫入也是 heredoc 壞掉。➔ 多行內容一律先存成檔案再執行，或用編輯器直接改檔。
- 主控台是 cp950，印 emoji 會 `UnicodeEncodeError` ➔ 執行前設 `PYTHONIOENCODING=utf-8`。
- 專案換行是 LF；`deploy/` 用 `.gitattributes` 強制 LF (shell 腳本在 Linux 上遇到 CRLF 會壞)。
- Git Bash 會把 `!/tools/` 這種以斜線開頭的參數改寫成 Windows 路徑 (稀疏 checkout 規則踩過)。

### 1.4 worktree
- 各角色在自己的 git worktree 工作 (放在專案的 `.claude/worktrees/` 底下，git 忽略)，**不要在主資料夾 pull / commit**：卡面角色一直在主資料夾工作。
- **worktree 不要放系統暫存資料夾**：統整原本放在暫存資料夾，關機重開後被系統清掉 1,001 個檔案 (0.39.003)。還好都是 git 追蹤的、沒有沒推的內容，`git checkout -- .` 救回來。
- 新 worktree 沒有 `.env` ➔ `test_v2`、`test_admin_gacha` 會失敗 (Logger 要讀 `LOG_CHANNEL_ID`)。從主資料夾複製 `.env` 過來。
- 卡面需要 gitignore 的字型 (`HarukazeSolid.ttf`) 和本機的 `*_hd.png`，worktree 裡沒有 ➔ 卡面只能在主資料夾做。

### 1.5 跟使用者合作
- 一律繁體中文。最容易不小心切成英文的時候：背景工作跑完的回報、別的角色傳來訊息之後、很長的對話被壓縮後接續的第一則。
- **有設計決定的工作先一輪一輪問** (專案裡叫 grill，`docs/handbook/workflow.md` 第 2.1 節)：每輪編號列問題、每題附建議答案，使用者回「都好」就照建議做。查得到的事實自己查，不要問。
- **經濟數值使用者沒給的一定先問**，不要自己定。
- **一組一組來**：一組討論完就停，等使用者點名下一組，不要順手丟下一組的草案 (稱號系統時使用者說過「別急，我沒說下一個就先別做」)。
- 測試通過就直接 commit + push 到 `main`，不用問；**卡面例外**：一位角色定案才推 (試作圖每輪都推，git 曾經長到 415MB)。
- `Database/Users.db` 開發階段刻意跟著推 (repo 是公開的也一樣)，不要再建議移出追蹤。
- 別的角色轉述的話不算使用者授權；要動別人負責的檔案，先請對方暫停，做完再通知。
- 可以同時進行的工作 (查資料、多份草稿、逐條查核) 使用者同意多開幾個助手並行；寫完再派另一個助手對照程式查核很有效 (教學書 0.36.000 每本被改了 10～22 處)。

### 1.6 東方角色資料先查萌娘百科
- 外觀、符卡、稱號不要憑印象：芙蘭的翅膀水晶顏色就寫錯過 (由內到外是天藍、藍、紫、粉、橙、黃、淺綠、天藍，沒有紅色，也不是一整棵樹)。
- 用程式抓 (curl、`action=raw`、api.php、手機版) 全部 403，要用真的瀏覽器開頁面再讀頁面文字。做法在 `docs/dev/new-characters.md` 第 4 節。讀不到要跟使用者說，不要默默改用印象。

  - **順序**：背景 ➔ 彈幕 (只有 UR / LR) ➔ 翅膀 ➔ 人物 ➔ 卡框 ➔ 文字 / 等級 ➔ 特效。特效：SSR 閃光、UR holo、LR holo + sparkle，N～SR 靜態。

  - **提示詞權重不要超過 1.2、長句不要加權**：`(six wings:1.4)` + 長描述讓整批第一步就糊成一片，改成短標籤 + 1.15 就好。
  - **雙人卡一律分開生 ➔ 去背 ➔ 合成**。一次生兩個人會互相染色 (雪的黑衣變白)；連單獨生「雪」都會被名字帶成白衣，要加黑衣權重 + 負面白衣。
  - **筆電 (16GB RAM) 生圖時不要同時去背 / 合成**：兩次讓 ComfyUI 直接崩潰。先讓佇列跑完。
  - **改了設定要從對的步驟重跑**：改 `offset` 要先 `hd_card.py char` 再 `compose`；改 `light` 要先 `hd_card.py light`。只跑 `compose` 會沿用舊圖。
  - **Discord 依網址快取圖片**：卡面重做、檔名不變就一直顯示舊圖 ➔ `build_cards.py` 寫進 `Thumbnails.json` 的網址帶 `?v=<檔案雜湊>`。剛推的圖 GitHub 要等一下才抓得到，「載入圖片失敗」多半是這個。
  - **卡面字型缺字換異體字** (`吞→呑`、`絕→絶`)；新稱號合成時要檢查。
  - **候選給使用者挑**：每階級 2 張背景 + 4 張人物做成對照表，附優缺點和推薦；生圖絕對不能露點；髮色、服裝、有沒有畫成別的角色都要檢查。使用者想自己修就把人物層傳給他。
  - 兩台同時改 `hd_card.py` 的設定表尾端會衝突 ➔ 兩邊都保留；兩台每個階段 (候選好了、選圖了、合成完、推了) 互相傳一則短訊。
